# Паттерны курса

Паттерн проектирования — типовое решение повторяющейся задачи. Он описывает распределение обязанностей между классами и способы их взаимодействия.

Выбор паттерна зависит от задачи: создание объектов, отмена действий, уведомление об изменениях или замена поведения.

| Паттерн | Практика | Где в лабах |
| --- | --- | --- |
| Модель отдельно от окна | П1 | все лабы |
| Фабрика | П2 | лаба 2: фигура по инструменту и из файла. РПГ: враги и предметы |
| Команда | П2 | лаба 2 ★★: отмена и повтор. РПГ по желанию: действия в бою |
| Наблюдатель | П3 (в П1 неявно: `Click`) | лаба 3: входящие сообщения. Лаба 4: модель изменилась. РПГ: новый уровень |
| Стратегия | П4, П5 | лаба 4 ★★: локальный игрок, сетевой, бот. РПГ: поведение врагов |
| Состояние | П4 | лаба 4: этапы игры. РПГ по желанию: исследование, бой, торговля |

## Модель отдельно от окна

С лабы 1: модель хранит данные и правила и ничего не знает об окне, окно показывает модель и передаёт ей действия пользователя. В книгах это называют MVC (модель, представление, контроллер). Все паттерны ниже помогают держать это правило: модель сообщает о событиях, а не вызывает окно; поведение и создание объектов не размазаны по обработчикам кнопок.

## Фабрика

**Проблема.** Окно знает только имя инструмента (`"RectShape"`), в файле у фигуры записан тип строкой. Нужно получить объект нужного класса. Дублирование `switch` по строке в окне и в загрузке требует согласованно менять оба участка при добавлении фигуры.

**Решение.** Создание объектов собрано в одном месте. Остальной код просит у фабрики объект по имени и не знает конкретных классов.

```csharp
public static class ShapeFactory
{
    public static readonly Dictionary<string, Func<Point, Color, int, Shape>> Kinds = new()
    {
        ["LineShape"] = (p, c, w) => new LineShape(p, c, w),
        ["RectShape"] = (p, c, w) => new RectShape(p, c, w),
    };

    public static Shape Create(string kind, Point start, Color color, int width) =>
        Kinds[kind](start, color, width);
}

// окно: кнопок столько, сколько записей в словаре
foreach (var kind in ShapeFactory.Kinds.Keys) AddToolButton(kind);

// мышь нажата
_current = ShapeFactory.Create(_tool, e.Location, _color, _width);
```

**Применение.** Лаба 2: кнопки инструментов, нажатие мыши, загрузка из JSON. РПГ: `EnemyFactory.Create(level)` решает, какие враги на каком уровне; так же предметы у торговца и в сундуках.

**Когда применяется.** Один и тот же `switch` или цепочка `if` по названию типа встречается в двух местах и больше.

**Частая ошибка.** Фабрика есть, но в окне всё равно остался свой `switch` по инструменту. Тогда это не одно место, а два.

## Команда

**Проблема.** Отменить последнюю нарисованную фигуру легко: убрать её из списка. А как отменить удаление или очистку? И как вернуть отменённое по Ctrl+Y?

**Решение.** Каждое действие это объект, который умеет себя выполнить и отменить. История хранит выполненные команды в одном стеке, отменённые в другом.

```csharp
public interface ICommand
{
    void Execute();
    void Undo();
}

public class AddShapeCommand : ICommand
{
    private readonly Drawing _drawing;
    private readonly Shape _shape;

    public AddShapeCommand(Drawing drawing, Shape shape)
    {
        _drawing = drawing;
        _shape = shape;
    }

    public void Execute() => _drawing.Add(_shape);
    public void Undo() => _drawing.Remove(_shape);
}

public class History
{
    private readonly Stack<ICommand> _undo = new();   // что можно отменить
    private readonly Stack<ICommand> _redo = new();   // что можно повторить

    public void Do(ICommand command)
    {
        command.Execute();
        _undo.Push(command);
        _redo.Clear();          // новое действие: повторять больше нечего
    }

    // Undo: взять команду из _undo, вызвать у неё Undo(), положить в _redo.
    // Redo: наоборот.
}
```

Окно не меняет рисунок напрямую, а делает `_history.Do(new AddShapeCommand(_drawing, shape))`. Удаление и очистка это ещё две команды: очистка перед `Clear()` запоминает, какие фигуры были, чтобы `Undo()` вернул их.

**Применение.** Лаба 2 ★★: нарисовать, удалить, очистить, переместить. РПГ по желанию: действия в бою (атака, способность, предмет, побег) как команды; журнал боя это список выполненных команд.

**Когда применяется.** Нужны отмена и повтор разных действий, очередь действий или журнал «что было сделано».

**Частая ошибка.** Ctrl+Y через второй список фигур: так возвращается только нарисованное, а удаление и очистка не отменяются. Ещё одна: новое действие после отмены не очищает стек повтора, и Ctrl+Y возвращает то, чего уже не должно быть.

## Наблюдатель

**Проблема.** Сетевой клиент получил сообщение, и его надо показать в окне. Если клиент сам вызывает `chatForm.AddLine(...)`, он зависит от окна: без окна его не запустить, второе окно или журнал не подключить.

**Решение.** Объект объявляет событие и сообщает о нём. Кто подписан, тот и реагирует. Источник не знает своих подписчиков.

```csharp
public class ChatClient
{
    public event Action<ChatMessage>? MessageReceived;

    private void ReadLoop()
    {
        // ... прочитали строку из сети
        MessageReceived?.Invoke(message);     // кто подписан, не знаем
    }
}

// в окне
_client.MessageReceived += m => Invoke(() => _feed.Items.Add(m.Text));
// журнал подписывается так же, окно о нём не знает
_client.MessageReceived += m => File.AppendAllText("log.txt", m.Text + "\n");
```

Пример из лабы 1: `button.Click += AddButton_Click` — подписка на событие кнопки. Кнопка вызывает подписанные обработчики, не завися от их реализации.

**Применение.** Лаба 3: `ChatClient.MessageReceived`. Лаба 4: `Game.Changed`, окно подписано и перерисовывается, в том числе после хода соперника по сети. РПГ: `Hero.LevelUp`, на него подписаны окно характеристик и журнал.

**Когда применяется.** Модель или сетевой класс должны сообщить окну о чём-то, что случилось не по нажатию кнопки.

**Частая ошибка.** Событие пришло из потока сети, а обработчик сразу меняет элементы окна. Окно падает или ведёт себя странно. Изменения окна передаются в его поток: `Invoke` (WinForms), `Dispatcher.UIThread.Post` (Avalonia), `Platform.runLater` (JavaFX), `SwingUtilities.invokeLater` (Swing).

## Стратегия

**Проблема.** Враги ведут себя по-разному: один всегда бьёт, другой лечится при малом здоровье, третий убегает. Если писать это в бою через `if (enemy.Kind == "goblin")`, каждый новый враг меняет код боя, а поменять поведение во время игры нельзя.

**Решение.** Поведение выносится в отдельный объект за интерфейсом. Тот, кто им пользуется, вызывает метод интерфейса и не знает, какой объект внутри. Объект можно подменить.

```csharp
public interface IBehavior
{
    string Act(Enemy self, Hero hero);
}

public class Aggressive : IBehavior
{
    public string Act(Enemy self, Hero hero)
    {
        hero.TakeDamage(self.Strength);
        return $"{self.Name} атакует: -{self.Strength}";
    }
}

public class Enemy : Character
{
    public IBehavior Behavior { get; set; }
    public string TakeTurn(Hero hero) => Behavior.Act(this, hero);
}

// враг испугался: поведение поменяли на ходу
goblin.Behavior = new Coward();
```

Морской бой ★★ устроен так же: игра спрашивает у игрока ход, а игрок может быть локальным (ждёт щелчка), сетевым (ждёт сообщения) или ботом (выбирает клетку сам).

**Применение.** Лаба 4 ★★: локальный игрок, сетевой, бот. РПГ: поведение врагов.

**Когда применяется.** Одно действие выполняется несколькими способами, и способ выбирается или меняется во время работы программы.

**Частая ошибка.** Интерфейс стратегии есть, но бой всё равно проверяет `if (enemy.Behavior is Aggressive)`. Тогда стратегия ничего не дала.

## Состояние

**Проблема.** Игра проходит этапы: расстановка, мой ход, ход соперника, конец. Одно и то же действие на разных этапах разрешено или нет. Если этап хранить в окне (кнопка выключена, значит нельзя), бот или сеть обойдут эту проверку.

**Решение.** Этап хранится в модели, и методы модели сами решают, что можно на текущем этапе. Простая форма: перечисление и проверка в начале метода.

```csharp
public enum GameState { Placing, MyTurn, EnemyTurn, Over }

public ShotResult Shoot(int x, int y)
{
    if (State != GameState.MyTurn)
        throw new RuleException("Сейчас ход соперника");
    var result = _enemyBoard.Shoot(x, y);
    if (result == ShotResult.Miss)
        State = GameState.EnemyTurn;
    return result;
}
```

Полная форма паттерна: класс на каждое состояние с одинаковыми методами, игра хранит текущий объект-состояние и передаёт ему вызовы. Это нужно, когда этапов много и в каждом методе разрастается `switch` по этапу. Для лаб достаточно простой формы.

**Применение.** Лаба 4: `GameState`. РПГ по желанию: исследование, бой, торговля (в бою нельзя уйти в другую локацию, у торговца нельзя атаковать).

**Когда применяется.** Объект проходит этапы, и от этапа зависит, что ему можно.

**Частая ошибка.** Этап хранится строкой (`"my_turn"`) или проверяется только тем, что кнопка выключена.

## Одиночка: почему не надо

Одиночка (Singleton) это класс, у которого во всей программе один объект, доступный отовсюду: `Game.Instance`. Он часто встречается в чужом коде и в примерах из интернета, но в лабах не нужен. Любой класс может незаметно обратиться к `Game.Instance`, и по конструктору уже не видно, от чего он зависит. Две игры сразу (реванш, тест) с ним не сделать.

Объект можно создать один раз в начале программы и передать зависимым объектам через конструктор:

```csharp
var game = new Game();
var window = new MainForm(game);
var connection = new Connection(game);
```

## Java и Kotlin

|  | Java | Kotlin |
| --- | --- | --- |
| Интерфейс | `interface Command { void execute(); void undo(); }` | `interface Command { fun execute(); fun undo() }` |
| Реализация | `class AddShape implements Command` | `class AddShape(...) : Command` |
| Событие | интерфейс-слушатель `interface MessageListener { void onMessage(ChatMessage m); }` и список `List<MessageListener> listeners` | список лямбд `val listeners = mutableListOf<(ChatMessage) -> Unit>()` |
| Подписаться | `client.addListener(m -> ...)` | `client.listeners += { m -> ... }` |
| Сообщить | `for (var l : listeners) l.onMessage(m);` | `listeners.forEach { it(m) }` |
| Стек истории | `Deque<Command> undo = new ArrayDeque<>();` | `val undo = ArrayDeque<Command>()` |
